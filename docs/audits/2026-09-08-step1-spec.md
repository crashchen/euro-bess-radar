## 0. 复核结论对实现范围的修正（先读这段）

审核报告把 F1 写成需要贯穿全局的 interval-grid 契约工程。实际不是：

- `analytics.py`、`dispatch.py`、`cycle_frontier.py`、`simulation.py` 的**单日** replay **都已经是 per-day dt 推断**。
- 唯一错的是连续回放的 **run 级**推断：`src/simulation.py:575` 与 `:691`。
- 这个 bug 类在 analytics 里**已经被发现并修过一次**，只是没有同步到 simulation。原文见 `tests/test_analytics.py:1251` 的 docstring：
  > *"The pre-fix code used frame-mode dt=0.25h and solved the hourly day as 6 hours of wall clock."*

所以本 PR 是**把已验证的修法搬到同级模块**，不是新设计。

CC 复核新增的两点证据（比原报告更严重，必须被测试钉住）：

1. **方向不安全。** `_infer_interval_hours` 取 delta 的 **mode**（`analytics.py:77`）。15 分钟区间占多数 ⇒ mode=0.25 ⇒ 小时日被压缩（原报告的 −25%）；**小时日占多数 ⇒ mode=1.0 ⇒ 15 分钟日被膨胀 4 倍**。实测 1 MW 资产单日放电 96 MWh / 48 次满循环，`valid_days=6/6`，零告警。翻转阈值是 `H > 4Q`（H=小时日数，Q=15分钟日数）；配合 `MAX_CONTINUOUS_REPLAY_INTERVALS=576` 分块，任何 `5 ≤ H ≤ 20 且 Q=1` 的 chunk 都会高估。例：加载 `2025-09-11..2025-10-01`（正好 576 区间 = 单块）。
2. **正常 UI 路径可达。** 真实 `clean_prices("DE_LU", 2025-09-28..10-02)` 返回 264 行、0 NaN、0 filled、每日 24/24/24/96/96、全窗口 mode dt = 0.25。数据质量检查全绿，直接喂给 cockpit。不是合成构造。

## 1. 红线（做错了要打回）

- **不要**改 `analytics._infer_interval_hours` 的 mode 语义 —— analytics / dispatch / cycle_frontier 的 per-day 调用依赖它当前行为。
- **不要**在本 PR 实现 per-interval `dt` 向量。那是 Step 2（解 8 个跨日切换区 + `solve_joint_capacity_batch`），单独 PR。
- **不要**放宽 `_is_regular_utc_day`。
- **不要**新增 `status` 取值。`docs/design/dispatch-failure-contract-v1.md` / `-v2.md` 是 locked 契约，一律复用现有 `"invalid_input"`，只改 `message`。
- **不要**为了"修好" F2 而把 DA forward-fill 到 IDA 网格。那会让模型拿小时 DA 承诺去做每刻重报，是模型变更不是修 bug。
- **不要**改 `MAX_CONTINUOUS_REPLAY_INTERVALS`。
- 非有限价格行按**丢弃**处理（与 CLAUDE.md 既有约定 "bad timestamp/price/volume rows DROP" 一致），**不要**改成 RAISE。
- 不要顺手重构文件结构 / 改无关 caption / 动 Vault。

## 2. C1 · F1：连续回放按 cadence 断 run

### 位置
`src/simulation.py::_group_clean_runs`（770–843）。修这一处同时覆盖 `_simulate_continuous_da_replay`(575) 和 `_simulate_continuous_da_id_replay`(691)，两者共用它。

### 改法
在现有四类断点（日期不连续 / 空 / NaN / 非规则日 / size cap）之外，增加第五类：**当日的 interval cadence 与当前 run 已累积的 cadence 不同**。

- 每日 cadence 用 `_infer_interval_hours(pd.DatetimeIndex(day_df.index))` 取。该日已通过 `_is_regular_utc_day`（uniform delta 已保证），故 mode ≡ 唯一 delta，取值精确。
- 语义必须与 **size-cap 断点完全一致**（`flush()` 后**保留** `previous_date`，当日照常 append 进新 run），**不能**用 NaN/sparse 那条路径（`previous_date = None` + `continue` 会把那天丢掉）。
- SoC 仍跨段结转：`_simulate_continuous_da_replay:626` 的 `current_soc_frac = min(max(soc_start_frac, 0.0), 1.0)` 已经在 run 之间传递，无需改动。段尾重新施加 terminal-neutral 等式，与 size-cap 分段同为 **soft reset**。

### 披露（报告 F1 验收明确要求）
- `simulate_replay_batch` 的返回帧增加 attr **`n_cadence_splits: int`**（窗口单一 cadence 时为 0）。在 `src/simulation.py:478` 附近与 `carry_soc` / `carry_mode` 一起写入。
- `src/pages/simulation_cockpit.py` 多日回放面板，在 `_render_batch_kpis(...)` 调用之后（约 902 行）：当 `n_cadence_splits > 0` 时 `st.caption(...)`，内容须说明三件事——窗口跨越了市场分辨率切换、连续时域在切换点被切分、SoC 仍结转但段尾重新施加 terminal-neutral 等式。按仓库惯例做 **verbatim caption 常量 + 两层非自指 pin**。

## 3. C2 · F2：DA/IDA 跨分辨率 inner join 静默丢区间

两个消费面都要修。**Revenue 页那个面更重要**（用户更多），原报告把它放在脚注里。

### C2-a · cockpit 单日
`src/simulation.py::simulate_da_id_replay:279-288`。

inner join 之后，`merged` 行数与 **DA 当日行数和 IDA 当日行数都要一致**；任一侧被丢行即拒绝：


### C2-b · Revenue 页（analytics）
`src/analytics.py::calculate_two_stage_da_id_dispatch:1186`。

现有闸门只对着 DA 行数比：

```python
da_count = int(da_daily_counts.get(date, 0))
if da_count > 0 and len(sorted_group) < round(0.9 * da_count):
```

小时 DA + 15 分钟 IDA 并出正好 24/24 行，满分通过 —— 72 个 IDA 区间被静默丢掉。
按 `da_daily_counts` 同样的构造方式补一份 `ida_daily_counts`，加对称闸门；未通过的日计入 `excluded_days_due_to_missing`（沿用现有 `excluded` 计数，不新增 attr）。

注意 blast radius：新闸门**只**新拒绝"IDA 比 DA 细"的情形；既有的"IDA 比 DA 稀疏"由原 DA 侧闸门处理，行为不变。跑全套确认没有既有测试依赖前者。
